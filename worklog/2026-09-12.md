## 세션 10 — [CC] MobaXterm·벤치마크 로드맵 배치 E: 세션 매니저 · 결과↔터미널/파일/룰 · 호스트키 · Discovery · SFTP

형이 준 2차 로드맵(MobaXterm 17항목 + Wazuh/NetBox/Nmap/Greenbone/Rudder/OpenSCAP/Lynis/CIS-CAT/osquery/Salt 벤치마크) — "싹 다". 제품 철학(읽기전용·무잔류·오프라인)에 맞게 걸러 배치로 간다.

- **호스트 카드**(사이드바 트리 아래, `ui/host_card.py`): 선택 호스트의 OS(마지막 진단 env)·IP·메타(환경/중요도/역할/태그)·Profile·Last·GOOD/VULN/MANUAL/ERROR + [진단][터미널][SFTP][Discovery][결과]. 세션 매니저 = MobaXterm 세션 목록 + 자산 관리.
- **결과 → 터미널/파일/룰**(로드맵 16): 결과 탭 상세 위에 [터미널 열기][파일 열기(근거에서 뽑은 절대경로 콤보)][해당 룰(테스터)]. 파일은 SFTP 탭을 그 디렉터리로 열고 읽기 전용 뷰어까지 자동. 룰은 룰팩 탭에서 트리 선택 + 테스터.
- **터미널 탭 상태 점**: 연결 중(노랑)/연결됨(초록)/유휴 2분(회색)/종료(빈 원)/오류(빨강) — 탭 글자색.
- **호스트키**: 세션 공유 저장소(`hostkey.SESSION_KNOWN`) — 그전엔 연결마다 정책 객체가 새로 생겨 "기존 키" 를 기억 못 했다(재승인 반복, 키 변경 감지 불가). 키 변경 시 기존/현재 지문을 나란히 보여주는 다이얼로그, 기본 **접속 중단**, 명시적으로만 "기존 키 제거 후 재등록".
- **SSH keepalive/재시도**(설정 → 접속): 연결 단계만 재시도(네트워크 순단), 인증 실패·호스트키 거부는 즉시. **재접속 ≠ 룰 재실행** 유지.
- **크리덴셜 프로필**: 입력 다이얼로그 "같은 고객사의 같은 계정 호스트에 모두 적용"(기본 켬) — 메모리에만, 세션 종료 시 폐기.
- **점검 목적(rationale)**: 가이드 purpose/threat 를 가이드 텍스트 맨 앞·결과 상세·리포트 "점검목적" 컬럼에. Wazuh SCA 의 rationale 대응.
- **룰 변경 감지**(Wazuh 정책 변경→결과 무효): 진단 시 `provenance.rule_sha256` 기록(`RulePack.rule_shas`), 현재 룰팩과 다르면 결과 탭 "⚠ 룰 변경됨", 게이트 "룰 변경 후 재평가 필요" 항목.
- **Discovery**(Nmap 벤치마크, `orchestrator/discovery.py`): nmap 미동봉 — 대상 한 대에 잘 알려진 포트 17개 TCP connect + SSH/HTTP 배너, 크리덴셜 있으면 SSH 읽기전용 5명령(uname·리스닝 포트·프로세스·ORACLE_HOME/TOMCAT_HOME 후보). → 추천 프로파일(linux/windows/aix/oracle/web-was/cisco) → [진단]. 결과는 `Host.discovered` 에 저장.
- **SFTP**: 컬럼 이름/크기/수정시간/권한/소유자(longname 파싱), 드래그앤드롭(로컬↔원격), 업로드 확인(원격 잔류물 경고), 더블클릭·[보기] = **읽기 전용 뷰어**(2MB 상한, 값 마스킹, 찾기, 사본은 tmp/view 완전삭제 대상). 편집 기능 없음 — 제품 철학.
- 감사 기록 푸터(세션 시작/종료/입력 줄 수/마스킹 수).
- **멀티실행 탭**(로드맵 3·15): 체크 호스트 + 플랫폼별 명령(sh/PowerShell/장비 CLI) → 정책 검사 → 확인창("읽기 전용 ✓ · 대상 N대 · 예상 변경 없음") → QThreadPool 동시 실행 → 결과표/출력/txt → 마스킹 감사 기록 `logs/multiexec/`. 워커에서도 정책을 다시 봐서 UI 우회 불가. **명령 라이브러리** `data/command_library.yaml` 15종(System/Process/Security) + 사용자 등록(config `command_library`, 쓰기 명령은 등록 거부).
