### 3. 터미널 마스킹 검증 — 구멍 발견
`audit/terminal_recorder.py` 의 2중 장치(프롬프트 패턴 + 에코 부재) 중 **에코 부재 판정이 무력화되는 조건**이 있다.

원인: `_finish_line()` 이 Enter 시점에 `stale = any(now - t > ECHO_GRACE ...)` 로 즉시 판정한다.
입력이 한 덩어리로 들어오면 어떤 문자도 아직 "오래되지 않아" `stale=False` → 프롬프트 패턴만이 유일한 방어가 된다.

재현 (프롬프트 패턴 미매칭 상황):

| 시나리오 | 결과 |
|---|---|
| 붙여넣기 후 즉시 Enter | **평문 유출** `[IN] Hunter2!Secret` |
| 개행 포함 한 덩어리 붙여넣기 | **평문 유출** |
| 총 0.07초 초고속 타이핑 | **평문 유출** |
| 짧은 비번 `abc123` 빠르게 | **평문 유출** |
| (참고) 표준 sudo 프롬프트 | 마스킹 OK — 패턴이 방어 |

비밀번호 관리자에서 복사·붙여넣기는 현장에서 흔하다. 실사용 경로다.

기존 `tests/failure/test_terminal_recorder.py` 는 무에코 케이스를 전부 `dt=0.1` 로 잡아 시간이 흐르게 해놓아 이 구멍을 못 덮었다.

**수정 방향 — Enter 시점 즉시판정을 버리고 지연판정으로.**

```python
# 1) 상태 추가
self._deferred: tuple[str, float] | None = None   # (line, t_enter)
self._deferred_secret_hint = False

# 2) _finish_line(): pending 이 비었으면(=이미 다 에코됨) 즉시 평문 기록.
#    남아 있으면 판정을 미룬다.
def _finish_line(self, now):
    if self._secret_by_prompt:
        self._write("[IN] ***"); self.masked_inputs += 1
    elif not self._pending:
        if self._line:
            self._write("[IN] " + (mask(self._line) or ""))
    else:
        self._deferred = (self._line, now)      # 에코가 오는지 더 지켜본다
    self._line = ""
    self._secret_by_prompt = False
    self._tail = ""
    # 주의: _pending 은 비우지 않는다(에코 대조에 계속 쓴다)

# 3) on_output() 끝에서 호출
def _resolve_deferred(self):
    if self._deferred is None:
        return
    line, t0 = self._deferred
    if not self._pending:                       # 에코가 돌아왔다 → 평범한 명령
        self._deferred = None
        if line:
            self._write("[IN] " + (mask(line) or ""))
    elif self._clock() - t0 > ECHO_GRACE:       # 끝내 에코 없음 → 비밀
        self._deferred = None
        self._pending.clear()
        self._write("[IN] ***"); self.masked_inputs += 1

# 4) close(): 미해결 deferred 가 남아 있으면 '***' 로 확정(보수적)
```

이렇게 하면 붙여넣은 **비밀번호**는 끝내 에코가 없어 `***`, 붙여넣은 **명령어**는 에코가 돌아와 평문으로 남는다. 감사 가치를 잃지 않으면서 구멍이 막힌다.

**추가 권고 (같은 파일)**
- `PROMPT_PATTERNS` 에 `>`·`?` 종결 프롬프트와 PIN/passcode/OTP/인증번호 추가. 장비 CLI·Oracle 계열에서 `:` 로 안 끝나는 프롬프트가 흔하다.
- `on_output()` 의 `and self._tail.rstrip().endswith(":")` 조건은 정규식이 이미 `:\s*$` 를 요구하므로 중복이고, `>` 종결 프롬프트를 원천 차단한다. 제거 권고.

**추가할 회귀 테스트** (`tests/failure/test_terminal_recorder.py`)

```python
def test_pasted_password_is_masked(tmp_path):
    """비밀번호 관리자에서 붙여넣기 — 시간이 흐르지 않아도 마스킹돼야 한다."""
    r, clk = _rec(tmp_path)
    r.on_output(b"Enter your PIN> ")          # 패턴에 없는 프롬프트
    r.on_input(b"Hunter2!Secret")             # 한 덩어리
    r.on_input(b"\r")
    r.on_output(b"\r\nAccess granted\r\n")    # 에코 없음
    r.close()
    log = (tmp_path / "t.log").read_text(encoding="utf-8")
    assert "Hunter2!Secret" not in log
    assert "[IN] ***" in log

def test_pasted_command_is_still_recorded(tmp_path):
    """붙여넣은 '명령어' 는 에코가 돌아오므로 평문으로 남아야 한다(감사 가치 유지)."""
    r, clk = _rec(tmp_path)
    r.on_output(b"igtest@web01:~$ ")
    r.on_input(b"ls -la /etc")
    r.on_output(b"ls -la /etc")               # 에코
    r.on_input(b"\r")
    r.on_output(b"\r\ntotal 1\r\n")
    r.close()
    log = (tmp_path / "t.log").read_text(encoding="utf-8")
    assert "[IN] ls -la /etc" in log
```
