# InfraGuard 기능 목록

- 기준일: 2026-09-13 (커밋 `c8c8332`, 테스트 839개 통과, CI 통과)
- 형태: 고객사 PC에 반입해 구동하는 Windows 포터블 데스크톱 앱(PySide6, PyInstaller onedir, 약 116 MB). 설치·관리자 권한 불필요, 폐쇄망 전제(온라인 통신 없음).
- 목적: KISA 「주요정보통신기반시설 기술적 취약점 분석·평가 방법 상세가이드(2026)」 항목을 원격 자산에 대해 읽기전용으로 점검하고, 판정·근거·조치방법을 표준 리포트로 낸다.

- 한 흐름: **자산 등록/쿼리 → Discovery(추천 프로파일) → dry-run·사전검증 → 진단(체크포인트·재진단) → 판정·추적·위험도·예외 → 결과에서 터미널/파일/룰로 바로 → 품질 게이트 → 리포트/세션 zip → 종료 시 완전삭제**.

## 1. 접속 (transport)

| 방식 | 대상 | 구현 |
|---|---|---|
| SSH | Unix/Linux(AIX·Linux·Solaris·HP-UX), Oracle 호스트 | paramiko. 호스트키 TOFU(세션 메모리 공유), **키 변경 시 기존/현재 지문 나란히 + 기본 접속 중단**(명시적으로만 재등록), keepalive·연결 재시도, 비밀번호/키 인증, 1단 bastion(점프서버). 크리덴셜은 세션 메모리만 — 입력 시 같은 고객사·같은 계정 호스트에 일괄 적용 가능 |
| SFTP | 위와 동일 | 스크립트 번들 업로드·산출물 회수, GUI 파일 브라우저 |
| WinRM | Windows 서버·PC | pywinrm NTLM(5985/5986). PowerShell 수집 명령을 스크립트 1개로 묶어 1회 실행(배치 프리페치, 실패 시 개별 실행 폴백) |
| 네트워크 장비 | Cisco IOS, Juniper Junos | SSH 대화형 셸(invoke_shell). 프롬프트 기준 벤더 자동 판별 → 페이징 해제, 동일 명령 캐시, 프롬프트에서 호스트명 추출 |
| 로컬 | 개발·자체점검용 | subprocess. Windows 룰을 GUI가 도는 PC에 직접 적용 가능 |

플랫폼에 따라 트랜스포트가 자동 선택된다(windows/pc → WinRM, network → 장비 셸, 그 외 → SSH).
전송 오류·타임아웃은 판정이 아니라 **오류(ERROR)** 로 남는다(수동확인으로 위장하지 않음).

**Discovery**(호스트 카드): nmap 미동봉 — 대상 한 대에 잘 알려진 포트 17개 TCP connect + SSH/HTTP 배너, 크리덴셜이 있으면 SSH 읽기전용 명령(uname·리스닝 포트·프로세스·ORACLE_HOME/TOMCAT_HOME 후보)까지 → 서비스 태그 → **추천 프로파일** → [진단]. 결과는 자산에 저장.

## 2. 진단 방식 두 가지 (프로파일로 선택, 혼용 가능)

### 2.1 스크립트 번들
`rulepacks/kisa-2026/scripts/` 의 sh/sql 스크립트를 원격 격리 디렉터리(`mktemp -d`)에 올려 nohup 실행 → tar 회수 → 파싱 → 판정. 종료 시 원격 디렉터리 삭제.
번들: `aix-unix`, `oracle-db`, `web-was`(Tomcat·OHS·WebLogic). 호스트별 파라미터(`ORACLE_HOME`, `TOMCAT_HOME` 등)는 자산 편집에서 `NAME=value` 로 지정하며, 경로·식별자 문자만 허용한다(셸 메타문자 거부).

### 2.2 네이티브 룰 (대상에 아무것도 올리지 않음)
읽기전용 명령만 원격 실행해 판정한다. 룰은 **선언형 YAML**(`collect → extract → verdict`)로 쓰며, 코드 변경 없이 룰팩만 바꿔 확장한다.

- 명령은 상수만 허용(변수 치환 없음), 비교 연산자는 화이트리스트.
- `platforms` 와 `variants` 로 같은 룰 id에 플랫폼별 대체 명령·판정을 둔다(예: N-xx Cisco 기본 + Junos 변형).
- `shell: sh | powershell | raw` 로 실행 셸을 지정한다.
- 미매치 시 판정을 룰이 명시한다(`missing: NA | MANUAL`). 추측하지 않는다.
- 분기 로직이 필요한 소수 룰만 파이썬.

## 3. 룰 커버리지 (룰팩 `kisa-2026`)

| 영역 | 항목 | 실행 | 프로파일 |
|---|---|---|---|
| Unix/Linux | U-01 ~ U-67 (67) | 네이티브 SSH + AIX 번들 | `linux-native`, `aix-native`, `aix-server` |
| Windows | W-01 ~ W-64 (64) | 네이티브 WinRM(PowerShell) | `windows-native` |
| Oracle DB | D-01 ~ D-26 (26) | 네이티브 SSH(`sqlplus / as sysdba`) + 번들 | `oracle-native`, `oracle-db` |
| 네트워크 장비 | N-01 ~ N-38 (38) | 네이티브 SSH 셸, Cisco IOS + Junos 변형 | `cisco-native`, `junos-native` |
| 웹 서비스 | WEB-01 ~ WEB-26 (26) | web-was 번들 파싱 | `web-was` |

합계: 룰 221종(네이티브 195). 판정은 **양호(GOOD) / 취약(VULN) / 수동확인(MANUAL) / 해당없음(NA) / 오류(ERROR)** 5분류이며, 모든 판정에 수집 근거(명령 출력)가 붙는다.

**판정 추적(provenance)**: 네이티브 룰 결과마다 실행 명령(argv)·종료코드·출력 SHA-256·소요시간·수집 시각, 추출된 변수 값, 매치된 판정 절, 트랜스포트, 룰팩 SHA 가 함께 저장된다. "왜 취약인가" 에 판정 → 명령 → 출력 → 비교식 → 가이드 근거 순으로 답한다(결과 탭 상세·xlsx·html).

## 4. 룰팩

- 구조: `manifest.yaml`(framework/guide_version/author 메타 — 컴플라이언스 팩 단위(KISA 2026, 향후 CIS·ISMS-P·사내 기준), 번들·룰·프로파일·SHA-256 무결성) + `scripts/` + `rules/*.yaml` + `guide/`(가이드 항목별 판단기준·조치방법·사례).
- 무결성: 로드 시 SHA 검증. 룰팩 정체는 manifest.yaml 의 SHA-256 하나로 대표되며 모든 진단 결과에 기록된다(재현성).
- **명령 안전 정책**: 룰의 수집 명령을 정적 분석해 변경 명령(rm·chmod·systemctl restart·sed -i·파일 리다이렉트·SQL DDL/DML·PowerShell Set-/Remove-·reg add 등)이 하나라도 있으면 룰팩 실행을 막는다. 같은 정책을 실행 엔진이 명령 실행 직전에 다시 적용한다(파이썬 룰·배치 프리페치 포함).
- 가이드 연동: 각 룰의 `remediation`(조치방법)·판단기준·점검 사례를 가이드 원문에서 채워 넣는다. 결과 리포트와 수동확인 화면에 그대로 표시된다.
- **부분 룰팩 생성**: 룰팩 탭에서 플랫폼/분류/룰 단위로 체크한 항목만 묶어 zip 으로 내보낸다(컨설턴트가 고객 자산에 맞는 항목만 가져다닌다). 전체 내보내기도 가능.
- **가져오기**: zip 룰팩 업로드. 절대경로·`..`·심링크 항목은 거부.
- 여러 룰팩을 두고 전환·삭제할 수 있다.

## 5. GUI

| 탭/화면 | 기능 |
|---|---|
| 자산 사이드바(세션 매니저) | 고객사 → 분류 → 호스트 트리. 추가·편집·삭제, JSON 가져오기. **자산 쿼리** 필터(`os=linux env=PROD crit=CRITICAL,HIGH tag=dmz`, `!=` 제외, 자유 단어 부분일치)와 **동적 그룹**(쿼리 저장 → 새 자산이 조건에 맞으면 자동 포함 → 그룹 선택 = 전부 선택 → 진단). 자산 메타(환경/중요도/담당자/역할/태그) — 진단 결과에 당시 값이 스냅샷된다. 트리 아래 **호스트 카드**: OS·IP·메타·Profile·Last·GOOD/VULN/MANUAL/ERROR + [진단][터미널][SFTP][Discovery][결과]. 우클릭 메뉴 동일 |
| 대시보드 | 판정 카드·취약 분포(가이드 중요도 + 위험도)·호스트별 분포·최근 진단·**조치 현황**(전회 대비 조치됨/재발/취약 유지/신규 취약 + 조치율)·**취약점 중심**(Top Affected Assets, Top Findings — 더블클릭하면 결과 탭 검색) |
| 진단 | 호스트·프로파일 선택, 동시 실행 수·타임아웃, 호스트별 진행 상태, 중단. **실패·미완료 재진단**(같은 진단 id 로 오류·중단 호스트만 재실행, 완료분은 체크포인트 유지). **실행 계획(dry-run)**: 원격 접속 없이 프로파일이 플랫폼별로 실행할 명령·번들·예상 잔류물·정책 위반 수를 나열. **연결 사전검증**: probe 직후 파라미터 누락·권한(sudo -n)·sqlplus 유무·/tmp 여유·시간 편차를 확인해 진행 표에 표시(진단은 계속) |
| 결과 | 호스트×룰 표(판정 칩 색상), 매트릭스 뷰, 상세(근거·조치방법·판단기준·판정추적). **이전 진단 비교**("이전" 컬럼, "변경만" 필터) + **조치 분류**(조치됨/재발/취약 유지/신규 취약 컬럼·필터) + **위험도**(가이드 중요도 × 자산 중요도 → 심각/높음/중간/낮음, 판정과 별개) + **예외 승인**(보상통제·승인자·만료일, 판정은 그대로 취약, 만료 시 자동 표시). 상세 위 **[터미널 열기][파일 열기][해당 룰(테스터)]** — 하나의 취약점에서 SSH 세션·근거 파일(SFTP + 읽기 전용 뷰어)·룰 테스터로 바로 연결. 상세에 점검 목적(가이드 purpose)과 **⚠ 룰 변경됨**(진단 당시 룰 SHA ≠ 현재 → 재평가 필요). 리포트 내보내기(xlsx·html) 전 **품질 게이트**(호스트 완료·ERROR 0·수동확인 처리·근거·조치방법·룰팩 SHA·DB 무결성·만료된 예외·룰 변경) |
| 수동확인 | MANUAL 항목 워크벤치. 가이드 사례·판단기준을 옆에 띄우고 담당자가 판정·메모 입력. 확인 방법 템플릿(설정파일/운영 정책/관리자 인터뷰/운영환경/예외 승인/기타)이 사유 앞에 표준 접두로 붙는다 |
| 룰팩 | 룰팩 선택·전환, 플랫폼 → 분류 → 룰 3단 트리(그룹 체크박스, 부분체크), 룰 상세(가이드), 가져오기/전체 내보내기/선택 내보내기/삭제/**비교**(다른 설치본·zip 과 manifest diff: 추가·삭제·판정 조건 변경·메타·프로파일), 프로파일 목록. **Rule Tester**: YAML 룰에 수집 명령별 샘플 출력을 넣고 실전 평가기로 판정·판정식·추출값을 즉시 확인 |
| 터미널 | 호스트별 SSH 터미널 탭(pyte 에뮬레이션), 탭에 상태 점(연결 중/연결됨/유휴/종료/오류), 브로드캐스트. 입출력 감사 기록(세션 시작·종료·입력 수 푸터), 비밀번호 입력 마스킹 |
| 멀티실행 | 체크한 호스트들에 같은 **읽기 전용** 명령을 동시에(플랫폼별 sh/PowerShell/장비 CLI). 실행 전 정책 검사(rm·chmod·systemctl restart·리다이렉트 등 거부, UI·워커 양쪽) + 확인창(대상 N대 · 예상 변경 없음). 결과표·출력·txt 내보내기·마스킹 감사 기록. **명령 라이브러리**(System/Process/Security 15종 + 사용자 등록, 쓰기 명령은 등록 거부) |
| SFTP | 로컬(workspace)·원격 두 창, 컬럼 이름/크기/수정시간/권한/소유자, 경로 직접 입력, 새로고침, 드래그앤드롭·버튼으로 받기/보내기(업로드는 원격 잔류물 경고 후), 더블클릭·[보기] = **읽기 전용 뷰어**(2MB 상한, 값 마스킹, 찾기). 편집 기능은 의도적으로 없음 |
| 설정 | 동시 실행·타임아웃·출력 상한·sudo, 접속 타임아웃·**SSH keepalive·연결 재시도**(연결 단계만, 룰 재실행 아님)·유휴 잠금·터미널 기록, 리포트 형식·회사명, 작업공간 경로·용량·**종료 시 완전삭제 스위치**·지금 완전삭제 |

외관: 프레임리스 창 + 자체 타이틀바(드래그·더블클릭 최대화·가장자리 리사이즈), 거의 흑색 플랫 테마, 단일 인스턴스 잠금(두 번째 실행은 경고 후 종료).

## 6. 결과 · 리포트

- 저장: 작업공간 SQLite(`results`). 진단 id 단위, 호스트별 체크포인트.
- 마스킹: 근거 텍스트의 비밀번호·키·토큰 패턴 마스킹.
- xlsx: 요약 시트(메타·룰팩 SHA·전회 대비 조치 현황·집계 수식) + 결과 시트(호스트·룰·판정·근거·**조치방법**(취약/수동 행)·**판단기준**·판정추적·이전결과·변화).
- html: 단일 파일 리포트, 동일 컬럼.
- 레거시 CSV(기존 스크립트 산출물 4종)·텍스트 리포트 파싱 → 동일 결과 모델로 취합(Ingest 폴백: 구형 PC 현장은 스크립트만 수동 실행하고 결과만 넣는다).

- **진단 세션 패키지**(파일 메뉴): 자산·예외·진단 결과·감사 기록을 zip 하나로 내보내고 다른 PC 에서 가져온다. 크리덴셜은 구조적으로 포함되지 않는다(자산 모델에 없음). 현장 PC 진단 → 세션 내보내기 → 완전삭제 → 사무실 PC 에서 분석·보고서 생성 흐름.

## 7. 보안 · 잔류물 통제

- 크리덴셜은 세션 동안 메모리만(`Secret`), 디스크·로그·리포트에 기록하지 않음. 평문은 트랜스포트 계층에서만 꺼낸다.
- 작업 중 산출물은 작업공간에 두고 **종료 시 완전삭제**(설정 → 작업공간 스위치, 기본 켬. 자기 PC 검토용은 끄면 결과·자산 유지. 작업공간 통째 삭제, 읽기전용 속성 강제 해제, "완전삭제 후 종료" 메뉴·설정 탭 즉시 실행). 다른 인스턴스가 DB 를 잡고 있어 삭제가 막히는 경우를 단일 인스턴스 잠금으로 차단.
- 원격 서버: 번들 실행 디렉터리는 실행 후 삭제. 네이티브 룰은 아무것도 남기지 않는다.
- 모든 룰·스크립트는 읽기전용. 룰팩 로더가 조치형 명령을 거부한다.
- 터미널 세션 입출력 감사 기록(비밀번호 마스킹).
- 유휴 시간(기본 15분) 경과 시 메모리의 크리덴셜 세션 만료, 제품 코드에 네트워크 호출 없음(업데이트·텔레메트리 없음).
- 크래시 로그는 작업공간 `logs/` 에만 남고 완전삭제 대상에 포함.

## 8. 부속 스크립트 (`scripts/`)

| 스크립트 | 용도 |
|---|---|
| `build_exe.py` | PyInstaller onedir 빌드(`--clean`, `--no-guide` 로 가이드 제외 가능) |
| `sign_exe.ps1` | 코드 서명(인증서 지문 지정, 테스트용 자체서명 옵션) |
| `native_selfcheck.py` | 실환경 자체점검 CLI(`--transport ssh|winrm|netdev`, 프로파일·파라미터 지정, `--full` 로 판정 분포 출력) |
| `extract_guide.py` | 가이드 PDF → 항목별 YAML/JSON(판단기준·조치방법·사례) |
| `enrich_rules.py` | 룰 YAML·manifest 에 가이드 조치방법 채움 + manifest 재생성 |
| `gen_rules_windows.py` / `gen_rules_oracle.py` / `gen_rules_netdev.py` / `gen_rules_services.py` | W/D/N/WEB 룰 YAML 생성기 |
| `regen_manifest.py` | manifest SHA·프로파일·분류 재생성 |
| `build_rulepack.py` | CLI 로 부분 룰팩 zip 생성 |
| `rule_coverage.py` | 테스트 스위트가 각 룰의 어느 판정(GOOD/VULN/MANUAL/NA/ERROR)을 실제로 만들어 봤는지 표로(`--run` 으로 기록 생성) |

CI(`.github/workflows/ci.yml`): push 마다 manifest 재생성 드리프트 검사 + 전체 테스트 + 룰 fixture 커버리지 표.
