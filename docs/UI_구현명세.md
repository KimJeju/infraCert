## 3. 스레딩 모델 — 가장 중요한 제약

**Qt 위젯은 UI 스레드에서만 만진다.** paramiko 호출은 전부 워커에서 돌린다. 이 규칙이 깨지면 랜덤 크래시가 나고 원인 추적이 매우 어렵다.

```
UI 스레드                     워커 (QThreadPool / QThread)
────────────                  ──────────────────────────
사용자 조작        ──job──▶   SSH connect / probe
                              스크립트 업로드
위젯 갱신          ◀─signal─  실행 · 폴링
                              산출물 회수
                              파싱 · 정규화(순수 CPU)
```

### 3.1 클래스

```python
# ui/workers.py
class ScanWorker(QObject):
    """호스트 1대의 진단 전체를 담당. QThread 에 moveToThread 한다."""
    started        = Signal(str)                 # host_id
    stage_changed  = Signal(str, str)            # host_id, stage
    progress       = Signal(str, int, int)       # host_id, done, total
    host_finished  = Signal(str, object)         # host_id, HostResult
    failed         = Signal(str, str)            # host_id, message
    log            = Signal(str, str)            # host_id, line

class ScanController(QObject):
    """여러 ScanWorker 를 동시성 제한 하에 굴린다."""
    scan_started   = Signal(str)                 # scan_id
    scan_progress  = Signal(int, int)            # done, total
    scan_finished  = Signal(object)              # ScanResult
```

- 동시성 기본 5, 설정에서 1~20
- 호스트 하나의 예외가 다른 호스트에 전파되지 않는다. 워커 내부에서 전부 포획해 `failed` 로 변환
- **체크포인트**: `host_finished` 를 받을 때마다 즉시 `results.db` 에 기록. 앱이 죽어도 완료분은 남는다
- 취소: `QThread.requestInterruption()` + 워커가 단계 경계마다 확인. 취소 시에도 원격 정리는 반드시 시도

### 3.2 절대 금지

- 워커에서 `QWidget` 접근
- UI 스레드에서 `conn.connect()` / `exec()` / `download()` 호출
- `Secret` 을 시그널 페이로드에 실어 보내기 (`__reduce__` 가 막지만 큐 경유 시 참조가 남는다 — `cred_id` 만 넘긴다)

### 5.1 단계 표시 문자열

`remote_runner` 의 시퀀스를 그대로 노출한다. 현장에서 "어디서 막혔나"를 바로 알아야 한다.

```
연결 중 → 환경 점검 → 호환성 확인 → 작업공간 생성 → 업로드
→ 실행 중 → 산출물 회수 → 원격 정리 → 파싱 → 완료
```

정리 단계에서 실패하면 **완료로 넘기지 않고 `⚠ 정리 미완료`** 로 표시하고 남은 경로를 로그에 남긴다.

### 5.2 크리덴셜 입력 (`CredPromptDialog`)

- 진단 시작 시 대상들의 크리덴셜 중 세션에 없는 것만 물어본다
- 같은 계정을 여러 호스트가 공유하면 한 번만 입력 (`cred_id` 로 묶음)
- 다이얼로그: 계정 / 인증방식(비밀번호·키·에이전트) / 비밀번호 / 키 경로 / sudo 비밀번호
- **입력값은 즉시 `Secret` 으로 감싸 `CredentialSession` 에 넣는다.** `QLineEdit.text()` 로 받은 `str` 은 지역변수로만 두고 즉시 폐기
- `QLineEdit.setEchoMode(QLineEdit.Password)`, 클립보드 복사 비활성

### 5.3 호스트키 승인 (`HostKeyDialog`)

`SessionHostKeyPolicy` 의 `approve` 콜백이 워커에서 호출되므로, **UI 스레드로 넘겨 blocking 대기**해야 한다.

```python
# 워커에서
result = QMetaObject.invokeMethod(
    ui_bridge, "ask_host_key", Qt.BlockingQueuedConnection,
    Q_RETURN_ARG(bool), Q_ARG(str, host), Q_ARG(str, keytype), Q_ARG(str, fp))
```

다이얼로그는 지문(SHA256)을 크게 보여주고 `[승인] [거부]`. 키가 이전과 다른 경우는 **경고색으로 별도 문구**를 띄운다 — 중간자 공격 가능성을 사용자가 알아야 한다.

## 7. 터미널 (`TerminalPage`) — MobaXterm 축

### 7.1 구조

```
paramiko Channel.invoke_shell()
   │ (워커 스레드: 논블로킹 read 루프)
   ▼
data_received(bytes) ──signal──▶ UI 스레드
                                    │
                                    ▼
                              pyte.Stream.feed()
                                    │
                                    ▼
                              pyte.Screen (버퍼)
                                    │
                                    ▼
                          TerminalWidget.paintEvent()
```

`pyte` 는 순수 파이썬 VT100 에뮬레이터다. 컴파일 불필요해 PyInstaller 에 유리하고, 기존 스크립트의 ANSI 색상 출력(`[양호]` 초록 / `[취약]` 빨강)을 정확히 파싱한다. 검증 완료.

### 7.2 `TerminalWidget` 구현

```python
class TerminalWidget(QWidget):
    """QPlainTextEdit 이 아니라 QWidget + paintEvent 로 직접 그린다.

    이유: 셀 단위 색상/속성, 커서, 선택 영역을 정확히 제어해야 하고
          대량 출력 시 문서 모델 갱신 비용을 피해야 한다.
    """
    COLS_DEFAULT, ROWS_DEFAULT = 120, 32
```

- 폰트: 고정폭. `D2Coding` → `Consolas` → `Courier New` 순 폴백. 한글 폭 2배 처리(`QFontMetrics.horizontalAdvance`)
- `paintEvent`: `screen.dirty` 로 변경 라인만 다시 그린다. 매 프레임 전체 리페인트 금지
- 커서: 깜빡임 `QTimer` 200ms
- 입력: `keyPressEvent` → VT 시퀀스로 변환(방향키 `\x1b[A`, Ctrl+C `\x03`, Home/End/PgUp/PgDn, Alt 조합)
- 리사이즈: `resizeEvent` → 열/행 재계산 → `screen.resize()` + `channel.resize_pty()`
- 스크롤백: `pyte.HistoryScreen`, 기본 5000줄. 마우스휠·Shift+PgUp
- 복사/붙여넣기: `Ctrl+Shift+C/V` (Ctrl+C 는 SIGINT 로 전달)
- 우클릭 컨텍스트: 복사 / 붙여넣기 / 검색 / 로그 열기 / 폰트 크기

### 7.3 터미널 로깅 — 입력·출력 기록 + 비밀번호 마스킹

입력을 그대로 기록하면 `sudo` 비밀번호가 로그에 남는다. 요구사항(입력·출력 모두 기록)을 지키되 비밀은 남지 않게 한다.

```python
class TerminalRecorder:
    """입력·출력을 workspace/logs/terminal/<host>_<ts>.log 에 기록한다.

    비밀 입력 판별 2중 장치:
      A) 프롬프트 패턴 — 직전 출력이 비밀번호 요구로 끝나면 다음 입력 라인을 비밀로 간주
      B) 에코 부재   — 보낸 문자가 200ms 내 출력에 나타나지 않으면 에코가 꺼진 상태로 간주
    둘 중 하나라도 걸리면 해당 입력은 '***' 로만 기록한다.
    """

    PROMPT_PATTERNS = (
        r"\[sudo\] password for .*:\s*$",
        r"(?i)password\s*:\s*$",
        r"(?i)passphrase[^:]*:\s*$",
        r"(?i)enter .*password.*:\s*$",
        r"(?i)current password:\s*$",
        r"(?i)새 암호|비밀번호\s*:\s*$",
    )
```

추가 규칙:

- 기록 파일에도 `result/masking.py` 의 값 패턴 마스킹을 **한 번 더** 적용한다(사용자가 `cat /etc/shadow` 를 치는 경우)
- 에코 부재 판정은 **보수적으로**: 애매하면 마스킹한다. 로그가 덜 남는 것이 비밀이 남는 것보다 낫다
- 로그는 `workspace/logs/` 안에만 쓴다. Sanitizer 삭제 대상에 자동 포함
- 터미널 탭 헤더에 `⏺ 기록 중` 표시. 사용자가 기록되고 있음을 항상 알아야 한다

### 7.4 멀티 세션 · 브로드캐스트

- 터미널 탭 여러 개 동시 유지
- **명령 브로드캐스트**: 체크한 여러 터미널에 같은 입력 전송. MobaXterm 의 핵심 기능이고 다중 서버 진단에서 유용
- 브로드캐스트는 실수 위험이 크므로 툴바 토글 + 대상 탭 개수를 상시 표시

### 7.5 보안 경계 문서화

터미널은 **제한 없음**으로 결정했다. 그러면 다음을 명시해야 한다.

> 자동 진단(Bundle 실행)은 Read-only 이며 대상 시스템을 변경하지 않는다.
> 터미널 탭에서 사용자가 직접 입력하는 명령은 이 보장의 대상이 아니며 사용자 책임이다.

이 문구를 터미널 최초 오픈 시 1회 안내하고, 리포트의 감사 로그 절에도 포함한다.

메뉴바의 `[완전삭제]` 버튼은 종료 없이 같은 정리를 수행한다(현장 철수 시).

## 16. 구현자 주의사항 (요약)

1. **`Status` 를 만드는 코드를 새로 쓰지 마라.** `core.decision.decide()` 만 쓴다. UI 에서 "이건 그냥 PASS로 하자"가 나오는 순간 제품의 핵심 보장이 깨진다.
2. **`Secret.reveal()` 을 `transport/` 밖에서 호출하지 마라.** 테스트가 막고 있다.
3. **`workspace/` 밖에 파일을 쓰지 마라.** 예외는 실행 폴더의 `config.json` 과 `rulepacks/` 뿐이다.
4. **워커에서 위젯을 만지지 마라.** 시그널로만 넘긴다.
5. **원격 정리 실패를 조용히 넘기지 마라.** 항상 사용자에게 보여준다.
6. **네트워크로 나가는 코드를 넣지 마라.** 폐쇄망이다. 업데이트 확인·폰트 다운로드·텔레메트리 전부 금지.
7. 기존 테스트 70개는 계속 통과해야 한다.
