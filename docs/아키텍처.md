# InfraGuard Desktop — 아키텍처 설계 v2

- 작성일: 2026-09-09
- 형태: **고객사 PC에 반입·구동하는 Windows 데스크톱 애플리케이션(portable exe)**. 그 PC에서 인프라 자산에 원격 접속하여 진단을 수행하고 결과를 표준화한다.
- 근거: `InfraGuard_요구사항_명세서.md`, 개발목표 문서, 스크립트 자산 실사(`InfraGuard_명세_리뷰_갭분석_v2.md` §1)
- 이 문서는 Standalone CLI 전제의 `InfraGuard_Python_설계.md`를 대체한다. 그 문서의 core·parsing·result·reporting 계층 설계는 그대로 유효하며 본 설계에 흡수된다.

---

## 0. 확정된 결정

| 항목 | 결정 |
|---|---|
| 실행 위치 | **고객사 PC** (PuTTY 등으로 인프라에 접근하는 그 PC) |
| 배포 형태 | **Portable** — 압축 해제 후 실행. 설치 불필요, 관리자 권한 불필요 |
| GUI | Python + PySide6 (Qt) |
| 최소 사양 | **Windows 10 64bit 이상** |
| 구형 PC 대응 | Ingest 폴백 (스크립트 수동 실행 → 결과만 정규화) |
| 접속 대상 | SSH/SFTP + WinRM + DB + 네트워크 장비 |
| 크리덴셜 | **세션 동안 메모리만.** 디스크 미기록 |
| 잔류물 | 작업 중에는 저장, **종료 시 삭제** |
| 결과 반출 | 다중 경로 지원 (현장 정책에 따라 다름) |
| 점프서버 | 1단 bastion 지원 |
| 네트워크 | **완전 폐쇄망 전제.** 온라인 인증·업데이트·텔레메트리 일체 없음 |

### 0.1 최소 사양이 Win10 64bit인 이유

PySide6는 **32비트 휠이 존재하지 않으며**(`pip download --platform win32` → No matching distribution), Qt 6는 Windows 10 이상만 지원한다. Win7/8이나 32비트 PC에서는 설치 자체가 불가능하다.

Qt 5 계열(PyQt5·PySide2)로 내려가면 Win7까지 커버되지만 Python 3.8이 필요하고, 3.8은 2024년 10월 EOL로 보안 패치가 없다. **고객사 서버 계정을 다루는 도구를 EOL 런타임 위에 올리는 것 자체가 리스크**이므로 채택하지 않는다.

구형 현장은 기존 방식(스크립트 수동 실행) 그대로 두고 산출물만 받아 Ingest 모드로 처리한다. 그 현장에서도 결과 취합 부담은 사라진다.

## 1. 실행 위치가 결정한 것

exe가 도는 곳이 우리 노트북이 아니라 **고객사 PC**라는 점이 위협 모델을 규정한다.

### 1.1 소멸한 문제 (Standalone CLI 대비)

| 기존 갭 | 상태 |
|---|---|
| G-16 / R-02 AIX·HP-UX·Solaris에 Python 배포 불가 | **소멸.** 대상 서버에는 sh/ksh 스크립트만 올라간다 |
| G-13 `/tmp noexec` | **대부분 소멸** |
| R-01 glibc 호환 | **소멸.** 바이너리가 대상 서버에 올라가지 않는다 |
| G-28 CWD 오염 | **소멸.** 원격에서 `mktemp -d` 격리 |
| 망분리 다단 경유 | **완화.** 그 PC가 이미 인프라에 붙을 수 있는 위치다 |

### 1.2 새로 생긴 문제

| # | 문제 | 성격 |
|---|---|---|
| **N-01** | **고객사 PC 잔류물** | 크리덴셜·결과·로그가 우리가 통제하지 못하는 기계에 남는다. "왜 우리 서버 계정이 이 PC에 파일로 있냐"는 질문에 답할 수 없다. **최대 리스크** |
| **N-02** | **원격 서버 흔적** | 우리 스크립트와 산출물이 고객사 서버에 남는다. 삭제 실패 시 계약 위반 소지 |
| N-03 | 반입 심사 | exe 크기(PySide6 번들 200~250MB)와 서명 여부가 심사 통과에 직결 |
| N-04 | 세션 단절 | `TMOUT`·idle kill·네트워크 순단. 수십 분 걸리는 Bundle 실행 중 끊기면 결과 소실 |
| N-05 | 동시성 | 수십 대 병렬 접속 시 세션 관리·실패 격리 |
| N-06 | 대화형 장비 | 네트워크 장비는 SFTP 없음. expect 패턴 필요 |
| N-07 | 결과 반출 | 현장마다 정책이 다름. USB / 담당자 전달 / 기타 |
| N-08 | 감사추적 | 고객사 서버 접속 행위 자체가 기록 대상 |

**N-01과 N-02가 타협 불가 항목**이다. 나머지는 품질 문제지만 이 둘은 사고 문제다.

## 4. 크리덴셜 — 메모리 전용

### 4.1 원칙

```
고객사 서버 계정 정보를 고객사 PC의 디스크에 어떤 형태로도 기록하지 않는다.
암호화 보관도 하지 않는다. 잠긴 금고 파일조차 남기지 않는다.
```

암호화 보관을 배제한 이유는 기술이 아니라 설명 책임이다. 진단 종료 후 고객사 PC에 우리가 만든 계정 금고 파일이 남아 있으면, 그것이 아무리 잘 암호화되어 있어도 정당화하기 어렵다.

### 4.2 구조

```
접속 시점
   │
   ├─ UI 입력  또는  USB 자산프로파일에서 주입
   │
   ▼
CredSession (프로세스 메모리)
   │  Secret 래퍼로 감싼 상태로만 존재
   │
   ├─ transport 계층에서만 reveal()
   │
   ▼
프로세스 종료 / 세션 잠금 / idle 타임아웃(15분)
   │
   ▼
메모리 폐기
```

- 여러 호스트가 같은 계정을 쓰는 경우 세션 내 재사용. 매번 재입력하지 않는다
- USB에 암호화 자산프로파일을 두고 반입하는 경로를 제공한다. **금고는 USB에만 존재하고 PC에는 복사되지 않는다**
- idle 타임아웃 시 메모리 폐기. 재개하려면 재입력

### 4.3 Secret 래퍼

평문이 새는 경로를 타입 수준에서 차단한다.

```python
class Secret:
    __slots__ = ("_v",)
    def __init__(self, v: str): self._v = v
    def __repr__(self)  -> str: return "Secret(***)"
    def __str__(self)   -> str: return "***"
    def __format__(self, _) -> str: return "***"
    def __reduce__(self): raise TypeError("Secret is not picklable")
    def reveal(self) -> str: return self._v
```

`__reduce__` 차단이 중요하다. 직렬화 경로(체크포인트·큐·로그)로 평문이 빠져나가는 것을 막는다. `reveal()` 호출 지점은 transport 계층으로 한정하고 CI에서 화이트리스트를 검증한다.

## 5. 작업공간과 완전 삭제

### 5.1 배치

Portable 전제이므로 `%APPDATA%`·레지스트리·사용자 프로필을 사용하지 않는다. **실행 파일 위치 기준 단일 폴더**에 모든 것을 둔다.

```
InfraGuard/                       ← 압축 해제한 폴더 (USB 또는 PC)
├── InfraGuard.exe
├── _internal/                    ← PyInstaller onedir 런타임
├── rulepacks/
└── workspace/                    ← 작업 산출물 전부. 삭제 대상
    ├── assets.db
    ├── results.db
    ├── artifacts/<scan_id>/<host>/
    ├── logs/
    └── tmp/
```

`workspace/` 하나만 지우면 잔류물이 사라지도록 경계를 단순하게 유지한다. 이 경계는 `workspace/layout.py`에 단일 정의하고, 다른 모듈이 임의 경로에 파일을 쓰는 것을 코드 리뷰·테스트로 차단한다.

### 5.2 Sanitizer

종료 시 자동 실행하되, 사용자가 명시적으로 호출할 수도 있다.

```
1. 열린 핸들 정리 (SQLite 연결 종료)
2. workspace/ 하위 전체 삭제
3. 임시 폴더 잔여 확인 (%TEMP% 내 우리가 만든 항목)
4. 최근 문서 · 점프리스트 등록 여부 확인 및 제거
5. 삭제 검증 — 남은 경로가 있으면 목록 표시
```

주의: **파일 덮어쓰기(wipe)를 안전 삭제로 광고하지 않는다.** SSD·저널링 파일시스템·섀도카피에서는 논리적 삭제만 보장되며, 그 이상은 보장할 수 없다. 문서에 한계를 명시한다.

종료 시 결과를 아직 반출하지 않았다면 경고하고 삭제를 보류할 수 있게 한다. 사용자가 결과를 잃는 사고가 더 흔하다.

## 6. Transport

### 6.1 공통 인터페이스

```python
class Connection(ABC):
    def connect(self) -> None: ...
    def probe(self) -> RemoteEnvironment: ...        # OS·셸·권한·인코딩·명령
    def exec(self, argv: list[str], *, timeout: int,
             cwd: str | None = None) -> ExecResult: ...
    def upload(self, local: Path, remote: str) -> None: ...
    def download(self, remote: str, local: Path) -> None: ...
    def cleanup(self, paths: list[str]) -> CleanupReport: ...
    def close(self) -> None: ...
```

Orchestrator는 프로토콜을 모른다.

### 6.2 SSH (paramiko)

- 1단 bastion: bastion 채널을 `sock`으로 전달해 target 연결
- keepalive 활성화 (N-04)
- 호스트키: **`AutoAddPolicy` 금지.** 최초 접속 시 지문을 UI에 표시하고 승인한 것만 세션 내에 유지한다. `known_hosts`를 고객사 PC에 남기지 않는다(잔류물)
- sudo: `-n` 우선. 비밀번호 필요 시 stdin 전달, 명령행 노출 금지
- 대상 셸이 `ksh`/`sh`인 경우를 전제로 명령을 POSIX 범위로 작성

### 6.3 WinRM (pywinrm)

- HTTPS 우선. HTTP는 명시적 허용 시에만
- 5985/5986 차단 환경이 흔하므로 preflight에서 연결 불가를 명확히 구분한다. **WinRM 불가 → SKIPPED(사유 기록). 절대 PASS 아님**

### 6.4 네트워크 장비 (netmiko)

- 자산의 Cisco·Juniper·HP·Alteon·Aruba·Piolink 대응
- SFTP 없음 → 스크립트 업로드 불가. **명령 시퀀스 순차 전송 + 출력 수집** 방식
- 따라서 네트워크 장비는 Bundle이 아니라 `command_set`으로 별도 정의한다
- `terminal length 0` 등 페이징 해제를 preflight에서 처리
- 우선순위 최하

### 6.5 DB

- MVP: SSH로 DB 서버에 붙어 `sqlplus`·`mysql` CLI 실행 (현 자산이 이 방식)
- OS 인증(`/ as sysdba`) 우선. 비밀번호는 stdin 전달. **`user/pass@tns` 인자 형식 금지** (`ps` 노출)

### 6.6 Local

Ingest 모드. 구형 PC 현장과 반입 불가 환경 대응. `probe()`는 산출물 헤더에서 환경을 추출하고, 확인 불가 항목은 `null` + `environment_incomplete: true`로 남긴다. **추측해서 채우지 않는다.**

## 7. 원격 실행 시퀀스

```
1. 크리덴셜 입력/주입           (세션 메모리)
2. Connect                     bastion → target
3. probe()                     OS · 셸 · 권한 · 인코딩 · 명령 존재
4. Compatibility               실행 가능 Bundle 선별
5. mktemp -d                   원격 격리 작업 디렉터리
6. upload                      스크립트 + 파라미터
7. nohup 실행 + 폴링       ★   세션 끊겨도 계속 (N-04)
8. tar.gz 회수                 SFTP download
9. 원격 정리               ★   업로드본 · 산출물 · 임시디렉터리 삭제
10. 정리 검증              ★   삭제 실패 시 경고 + 경로 기록 (N-02)
11. Disconnect
12. (로컬) 파싱 → 정규화 → 마스킹 → 판정 → workspace 저장
```

**7번 `nohup` + 폴링**이 N-04의 해법이다. 백그라운드로 띄우고 완료 마커를 폴링한다. 세션이 끊겨도 재접속해 결과를 회수할 수 있고, `TMOUT`이 걸린 계정에서도 진단이 살아남는다. 자산의 F1 스크립트는 `find /` 전체 순회를 포함해 수십 분이 걸리므로 필수다.

**9~10번**이 N-02의 해법이다. 삭제를 시도만 하고 넘어가지 않는다. 실패 시 UI에 경고하고 남은 경로를 기록해 사람이 처리하게 한다. 조용히 남기지 않는다.

## 8. Orchestrator

- 기본 동시 5. UI에서 1~20 조정
- 호스트 하나의 실패가 다른 호스트에 영향을 주지 않는다
- **체크포인트**: 호스트 단위로 결과를 즉시 SQLite에 기록. 앱이 죽어도 완료분은 남는다. 재개 시 미완료 호스트만 실행
- 취소 시 원격 정리를 시도한다

## 9. 마스킹 — 이중 적용

| 경로 | 대상 | 지점 |
|---|---|---|
| 로그 | 크리덴셜·접속 정보 | `logging_/filters.py` (루트 로거 강제 부착) |
| 결과·리포트 | shadow 해시, 개인키, AWS 키, JDBC URL, SNMP community | `result/masking.py` (normalize 단계) |

증적 마스킹 패턴은 이전 설계와 동일하다. 결과가 고객사 밖으로 나가므로 회귀 테스트를 별도 스위트로 유지한다.

크래시 핸들러에도 마스킹을 적용한다. **크래시덤프에 크리덴셜이 남지 않아야 한다.**

## 10. 수동확인 워크벤치

현장 수작업 부담이 큰 지점이므로 UI 1급 기능으로 둔다.

- UNKNOWN 항목만 모아 한 화면에
- 좌: 항목 목록 / 우: 수집된 증적 원문 (검색·하이라이트)
- 판정 입력(양호/취약/해당없음) + 사유 기록
- **판정 출처를 결과에 남긴다**: `verdict_source: script | analyst`, `analyst_note`. 사람이 바꾼 판정을 스크립트 판정과 섞지 않는다
- 동일 항목을 여러 호스트에서 일괄 판정하는 경로 제공

## 11. 결과 반출 (N-07)

현장 정책이 다르므로 경로를 고정하지 않는다.

| 경로 | 산출 |
|---|---|
| 암호화 묶음 | 결과 전체를 암호 zip(AES) 1개로. USB 반출용 |
| 평문 보고서 | XLSX·HTML만. 원본 증적 제외 |
| 원본 포함 | `artifacts/` 원본까지 포함. 재분석 필요 시 |

모든 반출에 **평문 매니페스트**를 동봉한다. 반출 심사 담당자가 내용물을 확인할 수 있어야 하며, 여기에는 파일 목록·개수·크기·해시만 담고 내용은 담지 않는다.

## 12. 패키징

- PyInstaller **onedir** (onefile 금지 — EDR 오탐·기동 지연·`%TEMP%` 잔류)
- 예상 크기 200~250MB. zip 배포
- Windows 코드 서명 — 반입 심사 통과에 직결되므로 우선순위 높음
- `--noconsole`. 크래시 로그는 workspace 내부로
- **온라인 동작 전무**: 업데이트 체크·라이선스 인증·텔레메트리·폰트 다운로드 없음. 폐쇄망에서 지연이나 실패를 유발하는 네트워크 호출이 하나라도 있으면 안 된다

## 13. 개발 순서

### Step 1 — 수직 슬라이스 (SSH 1대)

```
credentials(session·Secret)
  → workspace(layout·manager·sanitizer)
  → assets(models·store)
  → transport.ssh + preflight
  → orchestrator.remote_runner (upload·exec·download·cleanup)
  → parsing.legacy_csv + 프로파일 1종
  → core.decision + result.masking
  → reporting.xlsx
  → 최소 UI (자산 등록 · 크리덴셜 입력 · 실행 · 결과 표 · 완전삭제)
```

**완료 조건**

1. 리눅스 서버 1대를 등록하고 접속 크리덴셜을 입력한다
2. 기존 `unix_infra_script.sh`를 업로드·실행하고 결과 XLSX를 얻는다
3. **원격 서버에 흔적이 남지 않음을 검증한다**
4. **완전 삭제 후 로컬 PC에 크리덴셜·결과 잔류물이 없음을 검증한다**
5. 프로세스 메모리 덤프에서 평문 비밀번호가 로그·파일로 새지 않음을 확인한다

3·4·5가 기능보다 우선한다.

### Step 2 — 다중 호스트
Orchestrator 동시성 · 체크포인트 · 진행 뷰 · bastion 1단 · 실패 격리

### Step 3 — 결과 품질
파서 프로파일 4종 · Rule Pack 로더 · `provides` 대조 · 수동확인 워크벤치 · HTML 리포트

### Step 4 — Windows 대상
WinRM · `ps1`/`bat` 자산 흡수 · CP949 산출물 처리

### Step 5 — DB · 네트워크 장비
DB는 SSH 경유 CLI. 네트워크 장비는 netmiko `command_set`

### Step 6 — 운영 품질
감사 로그 · 자산 일괄 임포트 · 반출 경로 · 리포트 서식 · 패키징/서명

## 14. 보안 검증 항목 (자체 진단)

이 도구가 고객사 크리덴셜과 진단 결과를 다루므로 정기 검증한다.

- 크리덴셜 디스크 기록 경로 부재 (로그·체크포인트·pickle·크래시덤프 포함)
- `Secret.reveal()` 호출 지점 화이트리스트 준수
- `workspace/` 외부 파일 생성 부재
- Sanitizer 삭제 누락 및 검증 정확성
- SSH 호스트키 검증 우회 경로 부재
- 원격 명령 조립 시 인자 배열 사용 (셸 문자열 결합 금지)
- 업로드 스크립트 무결성 (Rule Pack 해시)
- 회수 압축파일 해제 시 path traversal
- 원격 정리 누락
- 자산 프로파일 파싱 안전성 (외부 파일)
- 폐쇄망에서 발생하는 아웃바운드 호출 부재
